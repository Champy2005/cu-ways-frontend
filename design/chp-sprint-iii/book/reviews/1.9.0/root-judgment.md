# 1.9 design judgment · 31 October 2026

The local HTML iteration passes root and fresh independent review in the scope
recorded below. Purple was explicitly rejected and removed from supporting
actions, progress and the reserved lab accent. The slate-blue / blue-teal
replacement remains **pending human color judgment**. Human-unvisited states
were retained; no model review grants human approval.

## Result

- Lifecycle label, icon and tone now come from one renderer. Accepted is identical
  in the lab, My Jobs, completion and cancellation. Hosts cannot repaint or clone
  the atom through the supported boundary without failing checks.
- Six explicit action roles distinguish commitment, useful task, supporting task,
  safe alternative, utility and quiet acknowledgment. Quiet text hover stays
  transparent. Keep job/In Progress are outlined; final confirmation stays last
  vertically. Add delivery proof is a clear blue task action. Stop waiting is a
  visible utility. Content More has a visible boundary and adequate hit area.
- Inside-card and page Back links use the same atom. Desktop content inherits a
  bounded96rem fluid workspace; very-wide My Jobs uses two readable columns.
  Loaded/loading/recovery heading origins match without fixed coordinates.
- Removed a broad palette-preview anchor rule that could override canonical
  action ink. Fixed author held-start controls retaining disabled paint after
  activation; Resolve/Leave now reflect actual enabled state. Author copy clearly
  distinguishes held starts from reads with their own Stop waiting control.
- The machine index now uses resolved compiler symbols and shared-style/token
  edges. CLI inspection/impact/validation, negative ownership fixtures, stale
  checks and actual rendered identity/hierarchy gates replace a documentation-only
  consistency approach. Application adoption remains separate.

## Independent findings and root disposition

Accepted the US027 B03 checklist clarity finding: an Accepted job should not
assert it is In Progress in an unmet criterion. `In Progress status` names the
condition; the actual lifecycle badge remains Accepted. Retaken and inspected.

Declined removing the safe action’s focus based only on a URL-seeded ring. Actual
pointer opening has no focus-visible ring; keyboard opening correctly has one.
Keep that accessible distinction. The [visual report](visual/report.md) records
the two diagnostic images’ provenance caveat and source-pinned live observations.

The author R13 Resolve probe was inapplicable: those controls resolve starts,
while R13 is a read. Current C03 enabled→Resolve→disabled behavior and clarified
labels were inspected. No unsupported read-resolution feature was added.
